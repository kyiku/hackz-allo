# Codexレビュー依頼: GitHub Issue RPG の仕様・タスク

あなたは経験豊富なソフトウェアアーキテクト兼ハッカソン審査経験者として、以下のspecを批判的にレビューしてください。忖度せず、欠陥・矛盾・抜け・過剰を指摘してください。

## 読むべきファイル（このリポジトリ内）
- `.kiro/specs/github-issue-rpg/requirements.md` — 要件定義（EARS）
- `.kiro/specs/github-issue-rpg/design.md` — 技術設計
- `.kiro/specs/github-issue-rpg/research.md` — 技術調査ログ
- `.kiro/specs/github-issue-rpg/tasks.md` — 実装タスク（全50サブタスク）

## 前提コンテキスト
- ハッカソン作品。**技術点で勝ちたい**。開発は2人＋AI駆動。
- コンセプト: GitHubのissueをRPGの敵にし、鍛冶屋に依頼するとAI(Claude Agent SDK)が**実リポジトリに本物のTDDでPRを作る**。テストが1つ通るごとに敵HP-1、CI成功で撃破→auto-merge。倒すと得た**スキル/MCP/サブエージェント(パーティ)を装備するとAIが実際に強くなる**メタループ。逆方向に「酒場」でAIにissueを作らせる。
- 死守コア: 鍛冶屋依頼→TDD戦闘→PR→CI→撃破→報酬装備→次戦で強化、の縦スライス完走。

## レビューしてほしい観点
1. **要件カバレッジ**: tasks.md は requirements.md の全要件(5.1〜5.10, 6.1, 6.2, 7, 8)を漏れなくカバーしているか。抜けている要件・暗黙の前提は？
2. **実装目標の正しさ**: 各タスクの技術的前提は妥当か。特に —
   - Claude Agent SDK のストリーミング入力による「呪文の割り込み」
   - auto-merge の422回帰フォールバック（CIポーリング→通常マージ）
   - テストpassのリアルタイム取得（Vitest/Jest `onTestCaseResult` ＋ stdoutフォールバック）
   - 「パーティ＝サブエージェント数」を `query()` の `agents` にマップする設計
   - 装備(スキル/MCP)を `query()` の `skills`/`mcpServers` に注入する設計
   research.md の調査結論に誤り・楽観があれば指摘。
3. **依存順序とビルダビリティ**: タスクの順序で死守コアまで最短到達できるか。循環依存・前後関係の誤りは？縦スライス優先に組み替えるなら推奨順は？
4. **サイズ感**: 1〜3時間/サブタスクは現実的か。過大なタスク（分割すべき）・過小なタスクは？
5. **スコープ/リスク**: 2人＋ハッカソンで死守コアが間に合うか。削るべき/モック化すべき要素は？デモの信頼性リスク（生AI実行・時間・非決定性）への対策は十分か。
6. **抜け・矛盾**: 設計上の穴（エラー処理、状態整合、秘密情報の扱い、並列実行時の競合など）。requirements/design/tasks 間の不整合。

## 出力形式
- 重大度別（CRITICAL / HIGH / MEDIUM / LOW）に箇条書き。
- 各指摘に「根拠」と「推奨アクション（どのタスク/節をどう直すか）」を添える。
- 最後に「死守コアを最短完走するための推奨タスク順」を提示。
